# API Domain

The API domain manages the full lifecycle of APIs within the Control Plane — from registration through exposure to subscription. It acts as an abstraction layer above the Gateway domain, handling the business logic of who can access which APIs and under what conditions.

## Reconciliation Flow

```
Rover file applied
    │
    ├──▶ Api created (registered)
    ├──▶ ApiExposure created (gateway route configured)
    │
    └──▶ ApiSubscription created (by subscribing team)
            │
            ├──▶ ApprovalRequest created (granted at once if strategy = auto)
            ├──▶ Approval issued once the ApprovalRequest is granted
            └──▶ Gateway ConsumeRoute created (access granted)
```

The ApiSubscription is blocked while a decider must act on the ApprovalRequest. Between the grant and the issue of the Approval, it is processing. If no Approval is issued within 5 minutes of the grant, it is blocked with a message that points at the approval controller.

## Route Provisioning

When an **ApiExposure** is reconciled, the API operator provisions the gateway routes that make the API reachable — including across zone boundaries. It decides which routes to create based on where the API's subscribers live:

| Route created | When | Created from |
|---------------|------|--------------|
| **Primary** route | Always — one per exposure, in the provider's zone | `ApiExposure.Spec.Upstreams` |
| **Proxy** route | For each zone that has a subscriber but is *not* the provider's zone | The subscriber's zone + the provider zone's gateway URL |
| **Secondary** route | For each provider failover zone (`failover.zones`) | A copy of the provider's upstreams, placed in the backup zone |

A matching **ConsumeRoute** is then created for each approved subscription to grant the consumer access to the correct route (primary or proxy, depending on the consumer's zone).

For the meaning of each route type and how they forward traffic, see [Gateway Domain: Route Types & Cross-Zone Meshing](./gateway.mdx#route-types--cross-zone-meshing).

### LMS Issuer

When the primary route is provisioned, the operator writes `status.lmsIssuer` on the ApiExposure. It is the issuer of the Last-Mile-Security (LMS) tokens that the gateway of the exposure zone sends to the upstream. The value comes from the default API gateway preset of the exposure zone. Providers should configure their upstream to trust this issuer. The field is empty while the exposure is inactive, blocked, or not yet provisioned.

If provider failover is configured, the operator also writes `status.failoverLmsIssuers`: one `{zone, url}` entry per zone in `spec.traffic.failover.zones`, in spec order, holding the LMS issuer of that zone's default API gateway preset. When the exposure zone is unavailable, the gateways of these zones call the upstream directly, so the upstream must trust these issuers as well. Zones without an LMS issuer are skipped. The list is empty when no failover is configured and is cleared together with `status.lmsIssuer`.

The Projector persists both values, and the ControlPlane API exposes them as `lmsIssuer` and `failoverLmsIssuers` on the GraphQL `ApiExposure` type (not on the reduced `ApiExposureInfo` type).

### Subscription Readiness

An `ApiSubscription` reports `Ready=False / PreconditionNotMet` while the exposure
is missing the required primary, provider-failover, or proxy route reference.
This also clears a previously successful readiness condition.

After provisioning, local and remote subscriptions check condition-bearing
resources created or updated during reconciliation for explicit `Ready=False`
conditions. This includes
the primary and any subscriber-failover `ConsumeRoute`s, and, where applicable,
the `ApprovalRequest`, `RemoteApiSubscription`, and locally created proxy Route.
An explicit child `Ready=False` keeps the subscription at
`Ready=False / SubResourceNotReady`. Missing or unknown Ready conditions and child
`ObservedGeneration` are not checked. Child status changes trigger reconciliation.
Once the check passes, the subscription reports `Ready=True / Provisioned`.

## Domain Interactions

- **Rover domain** — Creates Api, ApiExposure, and ApiSubscription resources.
- **Gateway domain** — The API operator creates Route (primary, proxy, secondary) and ConsumeRoute resources on the gateway.
- **Admin domain** — Zones provide the gateway URLs and identity issuers used to wire up cross-zone proxy and failover routes.
- **Approval domain** — Subscriptions trigger approval workflows.
- **File Manager** — OpenAPI specifications are stored and retrieved for API metadata.
